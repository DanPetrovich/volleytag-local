# VolleyTag Local

Локальный разметчик индивидуальной статистики волейбольного матча. Ты смотришь видео, отмечаешь действия кнопками или голосом, а VolleyTag считает показатели и может отправить результат в Google Sheets.

Это рабочий пилот, а не полностью автоматическая система компьютерного зрения: игрок и действие пока определяются по твоим отметкам, зато разметка прозрачна и её легко проверить.

## Что умеет

- размечать приём подачи, атаку, подачу, блок и защиту;
- отдельно учитывать эйс, выбитый приём и блокаут;
- фиксировать таймкод, сет, счёт и комментарий;
- считать реализацию и эффективность атаки, качество приёма, давление подачей и защиту;
- принимать голосовые команды при удержании пробела;
- хранить события локально, экспортировать CSV/JSON и синхронизироваться с Google Sheets;
- работать с большими MP4 и перемоткой через локальный HTTP byte-range сервер.

Исходное видео никуда не загружается. При голосовой разметке во внешний API отправляется только короткий фрагмент с микрофона, записанный во время удержания пробела.

## Как это устроено

```text
видео на компьютере
        │
        ├── кнопка/горячая клавиша ───────────────┐
        │                                         │
        └── удержание Space → запись микрофона    │
                            ↓                     │
                    Speech-to-Text                │
                    (сейчас Groq Whisper)         │
                            ↓                     │
                    распознанная фраза            │
                            ↓                     │
                    текстовая LLM                 │
                    (сейчас GPT-OSS в Groq)       │
                            ↓                     │
                 JSON: действие + результат       │
                            └──────────────────────┤
                                                   ↓
                         локальные события → статистика → CSV/JSON/Google Sheets
```

Speech-to-Text и LLM — разные модели. Первая превращает звук в текст, вторая понимает смысл фразы вроде «принял переходящий мяч, довёл до связки».

## Быстрый запуск на macOS

Нужен Python 3. Внешние Python-пакеты не требуются.

```bash
git clone https://github.com/DanPetrovich/volleytag-local.git
cd volleytag-local
chmod +x start.command
./start.command
```

Можно просто дважды нажать `start.command` в Finder. Окно Terminal должно оставаться открытым. Для остановки нажми `Ctrl+C`.

После запуска:

1. Перетащи видео в большую область плеера или нажми «Выбрать файл».
2. Короткое нажатие `Space` включает или останавливает видео.
3. Удержание `Space` записывает голосовую отметку.
4. Буквы на кнопках работают как горячие клавиши, `←`/`→` перематывают на 5 секунд.

Ручной запуск на другом порту:

```bash
python3 range_server.py 8765
```

Затем открой <http://127.0.0.1:8765>.

## Подключение голосовой разметки через Groq

Сейчас один ключ Groq используется и для расшифровки аудио, и для текстовой LLM.

1. Создай аккаунт и API-ключ в [Groq Console](https://console.groq.com/keys).
2. Рядом со `start.command` создай файл `.groq-key`.
3. Вставь в файл только ключ, без кавычек и дополнительных строк.
4. Перезапусти `start.command` и разреши браузеру доступ к микрофону.

На macOS ключ можно безопасно сохранить прямо из буфера обмена:

```bash
umask 077
pbpaste > .groq-key
```

Не отправляй `.groq-key` в чат, issue или commit. Файл уже добавлен в `.gitignore`. Вместо файла можно задать переменную окружения `GROQ_API_KEY`.

Примеры фраз:

- «атака, забил, выиграли»;
- «атака, блокаут»;
- «подал эйс»;
- «поднял в защите, игра продолжилась»;
- «принял переходящий мяч, довёл до связки».

## Какие модели используются

Настройки находятся в `range_server.py`:

| Этап | Модель по умолчанию | Endpoint |
| --- | --- | --- |
| Звук → текст | `whisper-large-v3-turbo` | `/openai/v1/audio/transcriptions` |
| Текст → событие | `openai/gpt-oss-20b` | `/openai/v1/chat/completions` |

`whisper-large-v3-turbo` выбран ради скорости. Если важнее точность на шумной записи, попробуй `whisper-large-v3`. Актуальные поддерживаемые Groq модели и ограничения перечислены в [Groq Speech-to-Text](https://console.groq.com/docs/speech-to-text).

Список доступных именно твоему аккаунту моделей можно получить так:

```bash
curl https://api.groq.com/openai/v1/models \
  -H "Authorization: Bearer $GROQ_API_KEY"
```

Не полагайся навсегда на название модели из README: провайдеры добавляют и убирают модели. Для Groq проверяй [Models API](https://console.groq.com/docs/api-reference#models).

## Где искать другие LLM

Для второго этапа нужна недорогая текстовая модель, которая хорошо понимает русский и умеет стабильно возвращать JSON. Варианты:

- [Groq Models](https://console.groq.com/docs/models) — проще всего для текущего кода;
- [OpenAI API](https://platform.openai.com/docs/models) — потребуется другой ключ и base URL;
- [Mistral Models](https://docs.mistral.ai/getting-started/models/) — облачные модели и OpenAI-подобный API;
- [Hugging Face Hub](https://huggingface.co/models?pipeline_tag=text-generation) — каталог открытых моделей для локального или облачного запуска;
- локальные модели через [Ollama](https://ollama.com/library) — фраза не покидает компьютер, но потребуется установить Ollama и заменить HTTP-запрос классификатора.

При замене LLM сохрани контракт ответа:

```json
{
  "action": "defense",
  "result": "perfect",
  "detail": null,
  "rallyOutcome": null,
  "confidence": 0.95
}
```

После замены обязательно проверь набор реальных русских фраз: волейбольные термины «переходящий», «выбитый», «блокаут» универсальная LLM понимает не всегда.

## Где искать другие модели для звука

- [Groq Whisper](https://console.groq.com/docs/speech-to-text) — текущий вариант, минимум изменений;
- [OpenAI transcription models](https://platform.openai.com/docs/guides/speech-to-text) — облачные модели транскрибации;
- [Mistral Voxtral](https://docs.mistral.ai/capabilities/audio_transcription/) — облачная транскрибация и модели Voxtral;
- [whisper.cpp](https://github.com/ggml-org/whisper.cpp) — полностью локальный Whisper на CPU/Metal, без отправки голоса в облако;
- [Hugging Face ASR](https://huggingface.co/docs/transformers/tasks/asr) — каталог и запуск Whisper, Wav2Vec2 и других ASR-моделей.

Для полной приватности логичный следующий backend — `whisper.cpp`. На Apple Silicon он может использовать Metal, но его нужно отдельно установить, скачать веса и вызвать локальный процесс вместо Groq endpoint.

При подключении другого облачного Speech-to-Text замени метод `transcribe_with_groq()` в `range_server.py`. Он должен принять байты аудио и вернуть обычную строку на русском. Остальной конвейер менять не нужно.

## Схема разметки

| Элемент | Что считается | Исходы |
| --- | --- | --- |
| Приём | только приём подачи соперника | идеальный, позитивный, негативный, ошибка |
| Атака | собственная атака | очко, в игре, блок соперника, ошибка |
| Подача | собственная подача | эйс, выбитый приём, в игре, ошибка |
| Блок | собственный блок | очко, касание, блокаут |
| Защита | любой мяч не с подачи: атака, скидка, свободный или переходящий мяч | довёл до связки, просто поднял, не поднял |

## Подключение Google Sheets

1. Открой таблицу и выбери **Расширения → Apps Script**.
2. Замени `Code.gs` содержимым [`google-apps-script/Code.gs`](google-apps-script/Code.gs).
3. Добавь свойство сценария `VOLLEYTAG_TOKEN` со случайным длинным значением.
4. Создай развёртывание типа **Веб-приложение**: выполнение от своего имени, доступ — «Все».
5. Вставь URL, заканчивающийся на `/exec`, и токен в блок Google Sheets в VolleyTag.

Для автоматической настройки скопируй `config.example.js` в `config.local.js` и заполни endpoint и token. `config.local.js` исключён из Git.

## Логи и диагностика

Голосовые попытки записываются в `volleytag-voice.log` рядом с сервером. В лог попадают время, расшифровка Whisper, JSON классификатора и текст ошибки. Аудио и API-ключ туда не записываются. Лог исключён из Git.

Частые проблемы:

- **Space прокручивает страницу** — обнови страницу и убедись, что курсор не стоит в поле ввода;
- **микрофон запрещён** — разреши доступ для `127.0.0.1` в браузере;
- **«не понял» при нормальном голосе** — проверь точную расшифровку в `volleytag-voice.log`;
- **порт занят** — закрой старое окно Terminal с VolleyTag или запусти другой порт;
- **Groq 401/403** — проверь `.groq-key`, права аккаунта и доступность выбранной модели;
- **модель не существует** — запроси свежий список через `/openai/v1/models`.

## Локальный поиск игрока — эксперимент

В `vision/track_players.py` лежит первый автономный этап будущего поиска игрока №51. Он:

- находит людей моделью YOLO11;
- связывает detections во временные треки через BoT-SORT;
- сохраняет видео с временными ID;
- пишет все рамки и таймкоды в `tracks.csv`;
- собирает `tracks.jpg` с лучшим кадром каждого ID.

Это пока не распознавание конкретного человека. В спортивном видео трек часто рвётся после
перекрытия или поворота: один игрок может получить несколько ID. Следующий этап — объединить
такие куски по визуальному сходству (ReID) и редким кадрам, на которых читается номер 51.

Установка в отдельное окружение:

```bash
python3 -m venv .venv-vision
.venv-vision/bin/python -m pip install -r vision/requirements.txt
```

Пробный запуск на первых 60 секундах видео:

```bash
.venv-vision/bin/python vision/track_players.py /путь/к/матчу.mp4 \
  --output vision/runs/test \
  --max-seconds 60 \
  --stride 3 \
  --roi 40,70,1900,1020
```

`--device auto` сначала пробует Metal/MPS на Apple Silicon, затем использует CPU. Чем меньше
`--stride`, тем надёжнее трекинг и дольше обработка. Координаты `--roi` подходят только для
тестового видео 1920×1080; для другой камеры их нужно изменить или убрать параметр.

На MacBook Pro M3 Pro тестовый 30-секундный фрагмент при `stride=5`, `imgsz=960` и CPU был
обработан за 26,4 секунды — 1,14× быстрее длительности исходника. При этом 51 временный ID
показывает, что детекция уже работает, а объединение разорванных треков действительно необходимо.

Ultralytics распространяется отдельно и имеет собственные лицензионные условия. Перед
коммерческим использованием нужно проверить актуальную лицензию зависимости.

## Данные и приватность

- видео остаётся на компьютере;
- события хранятся в `localStorage` браузера;
- при голосовой разметке короткое аудио и текст отправляются выбранному AI-провайдеру;
- `.groq-key`, `config.local.js`, видео, экспорты и голосовые логи исключены из Git;
- для переноса событий используй резервную копию JSON.
